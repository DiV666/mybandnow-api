# Prisma Transactional Outbox

When the `rb` CLI generates a module, it defaults to MongoDB adapters. The `OutboxMongoRepository` and `OutboxEventBus` were originally designed for non-transactional Mongo operations.

When migrating to PostgreSQL with Prisma, we must implement a **TRUE Transactional Outbox** to ensure atomicity between the Aggregate save and the Domain Event outbox save.

Follow these rules when adapting or implementing PostgreSQL repositories:

## 1. Schema Definition

Ensure the `Outbox` table exists in `prisma/schema.prisma` inside the `Shared` context:

```prisma
model Outbox {
  id           String    @id @default(uuid())
  eventId      String
  eventName    String
  aggregateId  String
  payload      Json
  status       String    @default("pending") // pending | published | failed
  attempts     Int       @default(0)
  errorMessage String?
  publishedAt  DateTime?
  occurredOn   DateTime
  createdAt    DateTime  @default(now())

  @@index([status, createdAt])
}
```

## 2. Localized Transaction in the Repository Adapter

The CLI generates Use Cases assuming the transaction is handled INSIDE the infrastructure repository. To maintain compatibility with CLI-generated code, **do not wrap the entire Use Case in a transaction**.

Instead, adapt the `PrismaRepository` (e.g. `UserPrismaRepository`) by injecting `Shared.Outbox` into it, peeking at the events, and using `$transaction` locally.

```typescript
import { PrismaClientFactory } from '../../../../Shared/infrastructure/persistence/prisma/PrismaClientFactory.js';
import { Outbox, TransactionSession } from '../../../../Shared/domain/Outbox.js';

export class MyEntityPrismaRepository implements MyEntityPersistenceRepository {
  private client = PrismaClientFactory.createClient();

  constructor(private readonly outbox: Outbox) {}
  
  async save(entity: MyEntity): Promise<void> {
    const data = entity.toPrimitives();
    
    // Peek at domain events without clearing them so the use case can still publish to EventBus
    const events = entity.pullDomainEvents({ drain: false });

    await this.client.$transaction(async (tx) => {
      await tx.myEntity.upsert({
        where: { id: data.id },
        update: data,
        create: data
      });
      
      if (events.length > 0) {
        await this.outbox.save(events, tx as unknown as TransactionSession);
      }
    });
  }
}
```

## 3. Dependency Injection Update

Make sure to inject the `Shared.Outbox` dependency into the repository in the module's dependency file (e.g., `mybandnowDependencies.ts`):

```typescript
  container
    .register('Mybandnow.MyEntity.MyEntityPrismaRepository', MyEntityPrismaRepository)
    .addArgument(new Reference('Shared.Outbox'));
```

**Why this works:**
1. The UseCase calls `persistenceRepository.save()`. The repository starts a local `$transaction` block, saves the entity, and saves the events to the Outbox atomically.
2. The UseCase then calls `eventBus.publish()`. The `OutboxEventBus` defers the RabbitMQ publish (`setImmediate`) to the background, reading the pending events.
3. This precisely mirrors how the MongoDB adapter behaves without requiring modifications to the application layer.
